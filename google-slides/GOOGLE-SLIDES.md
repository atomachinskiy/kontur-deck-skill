# Kontur Deck × Google Slides — рабочий слой

Как собирать деки Контура нативно в Google Slides: программно, через `presentations.batchUpdate`.
Результат — полностью редактируемый файл, который любой человек в Контуре правит руками.
Проверено в бою 2026-07-12 (сэмпл + каталог макетов на рабочем аккаунте).

## Когда этот путь, а когда другие
- **Google Slides (этот слой)** — дека уйдёт людям в Контуре на совместную правку; нужна нативная гугловая ссылка; контент важнее пиксель-перфекта. Качество ≈ 85% HTML-пайплайна.
- **HTML → PDF/PNG** (`kontur-deck.css`) — максимум контроля: тонкая типографика, сложные композиции, схемы. Не редактируется получателем.
- **Native PPTX** — когда просят именно .pptx по офиц. шаблону (см. SKILL.md).

## Система координат и сетка
- Дефолтная презентация 16:9 = **720 × 405 pt**. Все размеры задавай в `unit: "PT"`.
- Наша HTML-сетка 1600×900 px переводится коэффициентом **0.45** (px × 0.45 = pt).
- Поля: 30 pt слева/справа (= 64 px в HTML-системе). Контентная ширина 660 pt.
- Служебный слой (chrome): label 9 pt капсом сверху слева, вордмарк «Контур» 12 pt/700 сверху справа, номер страницы 8 pt снизу справа. У полноэкранных вставок и титула номера нет.
- Кегли, проверенные на 720×405: заголовок слайда 26 pt, титул 44 pt, тезис 40 pt, большие цифры 110-120 pt, текст карточек 11 pt, подписи 9.5-10.5 pt.

## Цвет и шрифт
- Токены из `tokens.json`: фон `#1C1C22`, карточка `#34353F`, текст `#FEFFFE`, вторичный `#9E9E9E`, светло-серый на карточках `#C9C9CE`, линии `#595959`. Акценты: purple `#844BEC` (основной), teal `#00BEA2`, orange `#FC7630`, blue `#366AF3`, magenta `#B850CF`, plum `#6B1D45` (фон финала/дивайдеров).
- Правило: **один ведущий акцент на слайд**; в мультикарточках — по одному акценту на карточку.
- Цвета в API — `rgbColor` с float 0..1 (хелпер `_hx`).
- **Montserrat есть в Google Fonts** → в Slides он нативный, подмен нет. Вес задавай через `weightedFontFamily: {fontFamily: "Montserrat", weight: 600}` — НЕ через `bold: true` (болд даст 700 и собьёт фирменный SemiBold).
- Межбуквенного трекинга (letter-spacing) в Slides API **нет** — капс-лейблы живут без разрядки, это ок.
- Межстрочный интервал: `updateParagraphStyle.lineSpacing` в процентах (105 = плотный заголовок, 118-130 = текст).

## Картинки, лого, иконки
- `createImage` принимает **только PNG/JPEG/GIF по публичному URL**. SVG не принимает.
- Лого продуктов Контура: CDN v2 `https://s.kontur.ru/common-v2/logos/v2/{product}/{product}-32@2x.png` — публичный, без VPN. **Тёмных PNG на CDN нет** (`-dark` есть только в SVG) → на тёмном слайде светлое лого кладём на белую плашку ROUND_RECTANGLE (см. слайд «2 цифры» в каталоге).
- Свои картинки (скрины, фото) — сначала выложить в публичный URL (Drive «anyone with link» отдаёт не прямой URL — не годится; проще временный хостинг или наш сервер), либо вставлять руками после сборки.
- **Рецепт хостинга (проверен 17.07.2026):** `ssh jino-vps`, docroot `/home/ubuntu/sites/kontur.ideafromai.ru/` → файл доступен как `https://kontur.ideafromai.ru/<путь>.png`. Google копирует картинку при createImage, после сборки временные файлы можно удалять.
- **Постоянные арт-ассеты обложки/финала** (PNG 620×844, вставка 279×379 pt на x=428, y=13): `https://kontur.ideafromai.ru/deck-assets/art-cover.png` и `.../art-final.png` — дефолты методов `cover_art`/`final_art`.
- Иконки-пиктограммы: у Slides нет инлайн-SVG → используем цветные примитивы (ELLIPSE-точки, квадраты-маркеры) как в шаблоне, или PNG-версии иконок.

## Таблицы
- `createTable` → `insertText` с `cellLocation` → стили текста per-cell → `updateTableCellProperties` (фон шапки `#34353F`, тело `#1C1C22`, `contentAlignment: MIDDLE`).
- Границы: `updateTableBorderProperties` с `borderPosition: ALL`, цвет `#34353F`, вес 1 pt — сетка почти растворяется в фоне, как в шаблоне.
- Высоту строк API задаёт минимальную по контенту; таблица «дышит» — не зажимай.

## Графики
- Нативные чарты в Slides API = только `createSheetsChart` (нужна таблица в Sheets). Для деки быстрее и чище **столбики из RECTANGLE-шейпов** (`bar_chart`): значение сверху 600-м весом, подпись снизу серым, один акцентный столбик.
- Donut/line — если правда нужны, собирай в Sheets и вставляй sheets-чарт, либо рендерь PNG нашим HTML-пайплайном и вставляй картинкой.

## Механика batchUpdate (гочи)
- **Один `batchUpdate` на всю деку** — быстрее и атомарнее, чем по слайду. 300-500 запросов в одном батче — норм.
- `objectId` должен быть **уникальным, ≥5 символов**. Дефолтный слайд презентации удаляй в конце (`deleteObject`).
- Порядок слайдов = порядок `createSlide`; вставка в позицию — `insertionIndex`.
- Точечная правка готового слайда: проще **удалить слайд и пересоздать** с `insertionIndex`, чем хирургически редактировать элементы (ID которых не сохранил).
- Вертикальное центрирование текста в боксе: `updateShapeProperties.contentAlignment: MIDDLE`, горизонтальное — `updateParagraphStyle.alignment`.
- Обводки у шейпов выключай явно: `outline: {propertyState: NOT_RENDERED}` — иначе дефолтная серая рамка.

## Обязательный QA перед отправкой
1. `deck.qa_thumbnails(dir)` — скачивает PNG всех слайдов через `pages.getThumbnail` (size LARGE).
2. **Просмотреть каждую миниатюру глазами** (Read): переносы, обрезки у правого края (текст-боксы за x=690 почти наверняка режутся), наезды.
3. Проверить правила текста: без длинных тире, ёлочки, в заголовках нет точек, имена полные.
4. Экспорт в PDF при необходимости: Drive API `files.export` mimeType `application/pdf`.

## Правила текста (всегда)
Без длинных тире (дефис или переписать) · «ёлочки» · ₽ после числа · NBSP после однобуквенных предлогов (в Slides — обычный пробел, API нормализует) · в заголовках нет точек · одна мысль на слайд · имя и фамилия полностью · минимум англицизмов.
